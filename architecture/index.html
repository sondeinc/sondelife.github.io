Architecture

One semantic mesh. Every surface.

Sonde turns a software system into a semantic mesh: source, builds, dependencies, resources, data flows, database schema, compliance posture, runtime signals, and probe results become queryable evidence that every interface can use.

The shape of the system

Whole-system perception

Language profiles, build resolvers, package metadata, logs, resource detectors, database and schema signals, and dependency behavior turn a repository into structured facts about the actual system.

Probe swarm

Racks coordinate probes for different purposes: AI safety, accessibility, localization, architecture, compliance, resources, project intelligence, code quality, and remediation.

Probe-on-probe reasoning

Probes can consume earlier probe results, so small deterministic observations compound into stronger system-level conclusions about change risk, fix priority, and code health.

Every interface, same logic

The browser-based Cockpit, CLI, SDK, MCP tools, LSP and VS Code extension, CI workflows, reports, and Scribe outputs all use the same semantic mesh instead of inventing separate rules.

Why the architecture matters

SondeQL asks targeted questions over the existing semantic mesh, so a team can inspect risk, ownership, architecture, compliance, accessibility, or remediation without building another brittle scanner.

Capability domains stay discoverable from manifests, so Explore follows the same source of truth as the Cockpit instead of becoming a hand-maintained marketing catalog.

The same evidence projects into Cockpit workflows, MCP tools, CLI commands, SDK calls, LSP diagnostics, lint gates, compliance artifacts, and authored reports.
