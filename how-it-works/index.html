How it all works

How Sonde turns a software system into evidence and fix plans

Eight kinds of system input feed the Sonde Semantic Mesh. The mesh runs a discover, analyze, query and prove pipeline, and emits three outcome tracks — AI guardrails; development; and compliance and accessibility — which together deliver a specific file and line, a deterministic fix plan, audit-ready reports, and a rerun that verifies improvement.

Sonde parses your codebase into a structural model, checks it against a deterministic set of rules, and turns the results into evidence your team can act on. Run it in CI, from the CLI, or straight from your editor -- it's the same check, the same result, every time.

Agentic usage of Sonde MCP

Sonde ships an MCP server, so the AI coding agent you already use can call the same deterministic analysis your team runs from the CLI and in CI. One command registers it with the agent hosts installed on your machine.

From inside a session, an agent can analyze code from a chosen facet such as health, complexity, or dependencies; query the semantic graph to find symbols, trace callers and callees, measure blast radius, and read context and snippets; review its own change with a delta review and a lint of the diff; and build a fix plan without changing anything.

When a fix is applied, it goes through verified transformers that roll the change back if its check fails, and actions that need consent ask you through the agent's host rather than taking the agent's word for it. Every answer points back to the same evidence, down to the file and line, so a reviewer can check exactly what the agent saw.
